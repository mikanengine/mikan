# Sprite sheets

A sprite sheet is one texture plus named rectangles into it. Mikan reads a
documented subset of the JSON that Aseprite (and tools imitating it) export, so
sheets can come from an existing art pipeline without a custom exporter. The
parser lives in `crates/assets/src/sheet.rs`; this document is the
contract.

## Format

```json
{
  "frames": {
    "player": {
      "frame": { "x": 0, "y": 0, "w": 32, "h": 32 },
      "duration": 100,
      "pivot": { "x": 0.5, "y": 1.0 }
    },
    "marker": {
      "frame": { "x": 32, "y": 0, "w": 32, "h": 32 }
    }
  },
  "meta": {
    "image": "atlas.png",
    "size": { "w": 96, "h": 32 }
  }
}
```

- **`frames`** must be a JSON object keyed by frame name. The array form
  Aseprite can also export is not accepted; frames are named because named
  lookups are what game code actually writes.
- **`frame`** is the pixel rectangle inside the sheet: `x`, `y`, `w`, `h`.
  Coordinates start at the top-left, matching the engine's world space.
- **`duration`** (milliseconds, optional) is preserved as metadata for
  animation code to use; the renderer does not animate anything by itself.
- **`pivot`** (optional, default `{ "x": 0.5, "y": 0.5 }`) is normalized
  within the frame: `(0, 0)` is the top-left corner, `(1, 1)` the bottom-right.
  `SheetFrame::center_for_pivot()` converts it into the world-space offset that
  turns a position into a frame center (a feet pivot `(0.5, 1.0)` places the
  frame half its height above the position, because `y` grows downward).
- **`meta.image`** is the texture file, resolved relative to the JSON file by
  `SpriteSheet::load`; `SpriteSheet::parse` keeps it as written.
- **`meta.size`** is the sheet's pixel size and must match the loaded texture
  for UVs to be correct; the demo checks this at startup.

Anything else — `frameTags`, `layers`, `slices`, `scale`, `spriteSourceSize` —
is ignored, so exports can grow with their tool without breaking the loader.

## Validation

`SpriteSheet::parse` and `SpriteSheet::load` reject a document with a specific
error instead of producing wrong frames:

| Condition | Error |
| --- | --- |
| The file cannot be read | `SheetError::Io` |
| The text is not valid JSON or not the accepted shape | `SheetError::Json` (with file and position when loaded from disk) |
| The same frame name appears twice | `SheetError::DuplicateFrame` |
| `meta.image` is absent | `SheetError::MissingImage` |
| The sheet size is zero | `SheetError::ZeroSheetSize` |
| A frame is zero-sized | `SheetError::ZeroFrameSize` |
| A frame reaches outside the sheet | `SheetError::FrameOutOfBounds` |
| A pivot is not finite or outside `[0, 1]` | `SheetError::PivotOutOfRange` |
| A frame is stored `rotated: true` | `SheetError::FrameRotated` |
| A frame is stored `trimmed: true` | `SheetError::FrameTrimmed` |

Duplicate detection uses a hand-written serde visitor because a JSON object —
and a derived map — silently keeps only one entry when a key repeats; a sheet
with two `player` frames is an authoring bug that must not render.

Rotated and trimmed frames are *refused* rather than rendered approximately.
Neither appears in Aseprite's default export settings; a caller that needs them
gets a clear error naming the frame.

## UVs and atlas bleeding

`SheetFrame::uv(sheet_size)` converts the pixel rectangle to the normalized
`UvRect` the renderer samples: the rectangle divided by the sheet size, then
**inset by half a texel on every side**. For the `player` frame above in a
96x32 sheet, that is `[0.5/96, 0.5/32] .. [31.5/96, 31.5/32]` instead of
`[0, 0] .. [32/96, 32/32]`.

The reason is filtering. A linear sampler at the exact edge of a frame blends
the frame's texels with whatever is on the other side — the neighbouring
frame in an atlas — which shows up as a one-pixel seam around sprites. The
inset keeps every linear sample a half texel inside the frame, so the seam
disappears. A one-texel frame would collapse to a point; `UvRect::inset`
allows exactly that (it keeps `min <= max`) because collapsing to the texel
center is the correct UV for a single texel, while an inverted rectangle would
sample nothing meaningful.

What it costs: at magnifications above 1:1 the outermost half texel of a frame
does not appear, so a frame is very slightly compressed against its pixel
rectangle. At 1:1 with nearest sampling — the pixel-art case — the mapping is
exact. This is the standard trade every texture atlas makes; it is documented
here so it is a decision, not a surprise.

Mikan does not pack atlases; the sheet is whatever the artist exported. Frames
may be flush with the sheet border (the inset stays inside the texture either
way).

## Producing sheets

The demo's own assets are generated by `scripts/generate_assets.py` (standard
library only, deterministic) and committed:

```bash
python3 scripts/generate_assets.py          # rewrite games/demo2d/assets
python3 scripts/generate_assets.py --check  # CI: fail if the files differ
```

```text
games/demo2d/assets/
    atlas.png    96x32: player, marker, and checker tiles side by side
    atlas.json   the sheet above naming those frames
    star.png     24x24 star with transparent corners (PNG alpha)
```

The demo loads this set through `mikan-assets` (`Image::load_png`,
`SpriteSheet::load`) and uploads the pixels as sRGB textures; see
`games/demo2d/src/assets.rs`. For any other tool chain, using the format above
is the entire integration.
